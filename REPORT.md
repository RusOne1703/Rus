## 1. Стратегия интеграции ассортимента Poizon/Dewu без официального API

Так как официального открытого API у Poizon нет, единственный путь "скопировать абсолютно весь ассортимент" — это использование **Web Scraping** (парсинга) и **Reverse Engineering** (реверс-инжиниринга) мобильных приложений.

### Технический подход:

1. **Реверс-инжиниринг мобильного приложения (App Reverse Engineering)**
   - Poizon (Dewu) в первую очередь мобильно-ориентированная платформа.
   - **Действие:** Необходимо перехватить трафик мобильного приложения с помощью инструментов (например, *Charles Proxy* или *mitmproxy* с подменой SSL-сертификатов на устройстве).
   - **Результат:** Вы найдете внутренние (скрытые) эндпоинты API, которые использует само приложение для подгрузки каталога, цен и фотографий. Их можно пытаться эмулировать в ваших скриптах.

2. **Масштабный парсинг (Web Scraping / App Scraping)**
   - Если перехват API затруднен из-за сложного шифрования подписей (sign/token), придется парсить данные имитируя действия пользователя.
   - **Инструменты:**
     - Для мобильного приложения: *Appium* (автоматизация действий на реальном устройстве или эмуляторе Android/iOS).
     - Для веб-версий (если есть доступные китайские веб-каталоги, агрегирующие Poizon): *Puppeteer* или *Playwright* на Node.js / Python.
   - **Обход блокировок (Anti-Scraping):** Poizon активно защищается от парсинга. Вам понадобятся:
     - **Мобильные или резидентные прокси (Mobile/Residential Proxies)** из Китая или Азии, чтобы запросы выглядели естественно.
     - Инструменты решения капчи.
     - Ротация User-Agent и отпечатков браузера (Fingerprints).

3. **Синхронизация и актуализация цен (On-Demand Parsing)**
   - Скопировать миллионы товаров один раз — половина дела. Цены на Poizon меняются динамически (зависят от размера, продавца и курса валют). Парсить весь каталог каждый час — невозможно.
   - **Эффективное решение:**
     - Храните в вашей базе данных только "скелет" каталога (Название, Бренд, Категория, Картинки, ID товара на Poizon). Этот каталог можно обновлять редко (например, раз в месяц).
     - Цены парсятся **в реальном времени** (или кэшируются на 1-2 часа), когда пользователь открывает карточку товара на `sotrue.ru`. Это радикально снизит нагрузку на ваши серверы и снизит риск блокировки, а также обеспечит 100% актуальность цен.

## 2. Рекомендуемая Архитектура

Поскольку `sotrue.ru` написан на Next.js (App Router), идеальная архитектура будет выглядеть так:

- **Frontend:** Next.js (уже используется), Tailwind CSS.
- **Backend парсинга:** Отдельный микросервис на Python (FastAPI). Python идеален для скрейпинга благодаря мощной экосистеме (Playwright, Selenium, bs4).
- **База данных:**
  - **PostgreSQL:** Для хранения пользователей, заказов и структуры каталога товаров.
  - **Redis:** Критически важен для кэширования парсинга! Если кто-то запросил цену на кроссовки Nike Air Force 1, сохраните ее в Redis на час. Если другой пользователь запросит их же — отдавайте из кэша, не дергая парсер.
  - **S3 Object Storage (например, Yandex Object Storage):** Картинки с Poizon обязательно нужно скачивать и хранить у себя, чтобы избежать блокировки (hotlinking) со стороны китайских серверов.

## 3. Рекомендации по улучшению сайта sotrue.ru (UX/UI, SEO, Бизнес)

Сайт выглядит минималистично и современно, но для масштабирования в "маркетплейс" требуются доработки:

**1. Доверие и Social Proof (Социальное доказательство)**
- Пользователи боятся переводить деньги за границу.
- **Действие:** Добавьте на главную страницу блок с живыми отзывами (интеграция из Telegram/VK/Trustpilot). Покажите реальные фото распаковок ваших клиентов с фирменными бирюзовыми бирками Poizon. Подробно распишите, как работает этап "Legit Check".

**2. Улучшение каталога и умный поиск**
- При росте ассортимента поиск становится главным инструментом.
- **Действие:** Внедрите умный морфологический поиск с исправлением опечаток (например, через Elasticsearch, Meilisearch или Algolia). Пользователь должен ввести "найк джордан" и получить релевантную выдачу.

**3. Интерактивный калькулятор на главной**
- Новичкам сложно понять ценообразование.
- **Действие:** Сделайте калькулятор максимально наглядным. Клиент вводит цену в юанях, выбирает категорию товара, и сразу видит разбивку: цена товара в рублях + комиссия сервиса + доставка до РФ. Это снимает вопросы к поддержке.

**4. Прозрачный личный кабинет и трекинг**
- После оплаты клиент испытывает стресс в ожидании (7-18 дней).
- **Действие:** Внедрите визуальный статус-бар заказа в личном кабинете (Выкуплен -> На складе в Китае -> Прошел Legit Check -> В пути -> В РФ). Интегрируйте API российских ТК (СДЭК, Boxberry) для бесшовного трекинга.

**5. SEO-оптимизация маршрутизации (Слаги)**
- Из системной памяти я знаю, что сейчас используются числовые ID товаров (например, `/product/12345`). Для маркетплейса это упущенный бесплатный трафик из Яндекса и Google.
- **Действие:** Перейдите на использование слагов (slug). URL должен быть человекопонятным: `sotrue.ru/product/12345-nike-dunk-low-panda`. Это кардинально улучшит ваши позиции в поисковой выдаче.

## 4. Промпты для ИИ (Cursor, ChatGPT)

Так как вы самостоятельно развиваете код, используйте эти готовые промпты в Cursor (или других AI IDE), чтобы быстро реализовать предложенные решения.

### Промпт 1: Создание микросервиса парсинга цен на Python (FastAPI)
```text
Act as an expert Python engineer.
Write a FastAPI microservice that accepts a Poizon product ID.
The microservice should use Playwright (async) to scrape the live price of the product from a specified target URL (we will use a web viewer for Poizon).
Implement user-agent rotation and basic retry logic (e.g., tenacity) in case of scraping failure.
Cache the successful result in Redis for 1 hour using the product ID as the key.
Return the price in JSON format.
```

### Промпт 2: Настройка On-Demand кэширования в Next.js (App Router)
```text
Act as a Next.js (App Router) expert.
I have a dynamic product page component in `app/product/[id]/page.tsx`.
Write the code to fetch the price dynamically from my Python microservice (http://localhost:8000/price/{id}).
Use Next.js built-in `fetch` with `next: { revalidate: 3600 }` to cache the price for 1 hour at the edge/server level.
Show how to implement a loading state using React Suspense or `loading.tsx` while the price is being fetched from the parser.
```

### Промпт 3: Улучшение SEO (Переход от ID к Slug в URL)
```text

Show me how to update the folder structure (e.g., `app/product/[slug]/page.tsx`) and the logic inside the page to parse the numeric ID from the URL (ignoring the text slug).
Also, demonstrate how to ensure canonical meta tags are generated correctly in the `generateMetadata` function.
```
