# Аудит и Промпт для Cursor: Рефакторинг SOTRUE.RU в "Amazon-подобный" e-commerce

Привет. Как договаривались, пишу технический аудит и хардкорное задание для Cursor. Наша цель: сделать так, чтобы сайт летал, Яндекс и Google видели 100% контента, а парсинг работал умно (товары и картинки лежат у нас, а парсятся только цены и размеры).

---

## Часть 1. Аудит текущей архитектуры (С прицелом на Amazon-level)

1.  **Client-Side Rendering (CSR) — Зло для SEO:**
    Если карточки товаров или фильтры в каталоге рендерятся через `"use client"` и `useEffect` с запросом к API из браузера клиента, поисковые боты (особенно Яндекс) могут не дождаться выполнения JS. У Amazon 100% контента (HTML) приходит сразу с сервера. Нам нужно уйти от клиентского рендеринга контента.
2.  **Синхронизация Каталога (Официальное API vs Парсинг):**
    У вас есть официальное API. Отлично! Значит, мы можем выкачать всю базу товаров (названия, описания, метаданные) и **скачать все картинки на свой сервер/S3**. Это убьет зависимость от китайских CDN и ускорит загрузку. Парсинг (Playwright/Скрипты) нужно оставить **только** для актуализации цен и размерной сетки.
3.  **Логика Вставки ссылки (Заявка / Корзина):**
    Функционал добавления по ссылке на страницах `/cart` и `/buy` должен работать молниеносно. Сейчас, если юзер вставляет ссылку с Dewu, бэкенд должен мгновенно (через API или кэш) отдать превью товара, а не заставлять юзера ждать 15 минут.

```markdown
# ТЕХНИЧЕСКОЕ ЗАДАНИЕ ДЛЯ CURSOR: "AMAZON-SCALE" РЕФАКТОРИНГ ПРОЕКТА SOTRUE.RU

Твоя задача — провести жесткий рефакторинг текущей кодовой базы. Сайт должен стать невероятно быстрым, 100% SEO-френдли (полностью видимым для роботов Яндекса и Google), и использовать правильную архитектуру работы с каталогом Poizon.

## ЗАДАЧА 1: Полный переход на Server-Side Rendering (SSR / SSG)
Мы полностью отказываемся от отрисовки основного контента на клиенте.
1. Открой файлы каталога (`app/catalog/page.tsx`, `app/catalog/[category]/page.tsx`) и карточки товара (`app/product/[id]/page.tsx`).
2. Удали директиву `"use client"`, если она там есть для оборачивания всей страницы.
3. Перепиши получение данных (fetch) на серверные компоненты. Данные о товаре должны запрашиваться напрямую из базы данных (Prisma/Drizzle/Fetch к внутреннему API) ВНУТРИ серверного компонента.
4. Клиентскими (`"use client"`) могут остаться ТОЛЬКО изолированные микро-компоненты:
   - Кнопка "Добавить в корзину" (состояние корзины).
   - Слайдер изображений товара (галерея).
   - Интерактивные фильтры каталога (при клике они должны менять URL через `router.push('?size=42')`, а сервер должен отдавать новый HTML, либо использовать Server Actions).

## ЗАДАЧА 2: Архитектура Каталога (Свой сервер + Синхронизация)
У нас есть доступ к официальному API, но цены меняются динамически.
1. **Изображения:** Перепиши компоненты `<Image>` так, чтобы они брали картинки с нашего собственного домена/S3 (например, `https://s3.sotrue.ru/images/...`), а не напрямую с `cdn-poizon-root`. Я (или бэкенд-разработчик) напишу воркер, который скачает все картинки. Твоя задача — настроить Next.js Image Optimization (`next.config.js` -> `remotePatterns`) на наш S3.
2. **Cron-стратегия (Инструкция для Бэкенда/Архитектуры):** Внедри архитектуру, при которой статические данные (ID, Имя, Бренд, Ссылка на фото) хранятся в БД жестко. А цены и наличие размеров обновляются по крону каждое утро или on-demand.
3. На стороне Next.js, на странице товара, цена должна подтягиваться либо из кэша (Redis), либо ревалидироваться (ISR: `revalidate: 3600` или tag-based revalidation).

## ЗАДАЧА 3: Рефакторинг модуля "Заказ по ссылке" (/buy и /cart)
Пользователь может вставить ссылку с Poizon/Dewu в поле ввода, чтобы добавить товар.
1. Проанализируй компоненты страниц `/buy` и `/cart`.
2. Реализуй мгновенную валидацию поля ввода (Regex для ссылок dewu.com / poizon.com / dw4.co).
3. При вставке ссылки, фронтенд должен делать POST запрос к нашему API (`/api/parse-link`).
4. Настрой UI так, чтобы во время парсинга ссылки юзер видел красивый Skeleton Loader, а после успеха — мгновенно появлялась карточка товара с фото, подтянутым размером и кнопкой "Подтвердить добавление".
5. Убедись, что если бэкенд не смог распарсить ссылку быстро (таймаут > 5 сек), юзеру предлагается ввести данные вручную (Артикул + Название), чтобы не блокировать воронку.

## ЗАДАЧА 4: Микроразметка и SEO-перфекционизм
Так как мы убрали CSR, HTML будет полным.
1. Внедрить `<script type="application/ld+json">` с Schema.org (Product) в серверный компонент товара. Там должны быть отзывы (хотя бы агрегированные), бренд, SKU, наличие (InStock).
2. Проверить генерацию H1, Title, Description. Они должны рендериться строго на сервере в функции `generateMetadata`.
```
